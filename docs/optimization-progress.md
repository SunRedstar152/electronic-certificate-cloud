## ผลทดลอง PNG

ภาพตัวอย่างจากแม่แบบต้นฉบับ 2000×1414 ใช้ข้อมูลสมมุติและลายเซ็นตัวอย่าง
บันทึกแต่ละแบบ 5 ครั้ง วัดค่ามัธยฐานของเวลา encode ไม่ใช่เวลาออกใบรวม

| วิธี | ไบต์ | เวลา encode มัธยฐาน |
|---|---:|---:|
| ค่าเดิม (ระดับ 6) | 44,737 | 22.00 ms |
| compress_level=9 | 43,576 | 61.65 ms |
| optimize=True | 43,576 | 60.73 ms |

ลดไฟล์ประมาณ 2.6% แต่ encode ใช้เวลาราว 2.8 เท่า จึงคงระดับ 6 เป็นค่าเริ่มต้น
สามารถตั้ง PNG_COMPRESS_LEVEL=9 หากยอมรับเวลาบันทึกที่เพิ่มขึ้นได้
ผลนี้ใช้กับภาพตัวอย่างนี้เท่านั้น ยังไม่ได้วัดกับแม่แบบพื้นหลังรูปถ่ายหรือโฮสต์ปลายทาง
ตรวจขนาดภาพ mode พิกเซลทุกจุด metadata และข้อความที่อ่านจาก QR ว่าตรงกันแล้ว
ไม่ใช้ pngquant หรือ oxipng

รันทดลองซ้ำจากโฟลเดอร์โครงการ:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_png.py
```

สคริปต์ใช้ฐานข้อมูล URL สมมุติที่เชื่อมต่อไม่ได้และไฟล์ภาพชั่วคราว ไม่อ่านหรือแก้ข้อมูลผู้ใช้

## งานที่ยังเหลือจากแผน 7 ขั้น

1. วัด RAM/เวลาการสร้างภาพรวมและ EXPLAIN ANALYZE บนข้อมูลตัวแทนขนาดใหญ่ก่อนเลือก index เพิ่ม
2. แคชพื้นหลังและฟอนต์แบบจำกัดขนาด พร้อม revision และ snapshot ของ batch ที่ยืนยันแล้ว
3. พรีวิวภาพย่อ จำกัดงานพรีวิวที่กำลังทำ และลดการอัปโหลดพื้นหลังซ้ำ
4. QR checkpoint และ URL version ที่ทนต่อการเปลี่ยน URL ระหว่างทำงาน; คำสั่งตรวจทั้งหมดต้องคงสิทธิ์ผู้ดูแล
5. แบ่ง batch เป็นช่วง พร้อม lease token, idempotency/unique constraint เดิม และทดสอบ crash recovery ของไฟล์กับ DB

ยังไม่อ้างว่าทำครบทั้ง 7 ขั้น และยังไม่มีตัวเลข RAM ก่อน–หลัง
ไม่เพิ่ม schema ทดสอบถาวร ไม่เปลี่ยนฐานข้อมูลจริง และยังไม่ได้เพิ่ม index โดยไม่มีผลวัดรองรับ

## อัปเดต: เลือกเน้นลดขนาด PNG ตามคำขอเพิ่มเติม

เปลี่ยนค่าเริ่มต้น PNG_COMPRESS_LEVEL จาก 6 เป็น 9 สำหรับการออกใบใหม่
และให้การอัปเดต QR ใช้ค่าบีบอัดเดียวกัน โดยไม่เปลี่ยนพิกเซลหรือ metadata
ผลทดลองซ้ำ 5 ครั้ง: ระดับ 6 = 44,737 ไบต์ / 21.96 ms; ระดับ 9 = 43,576 ไบต์ / 58.96 ms
การบีบอัดข้อความ metadata เพิ่มเติมได้อีกเพียง 11 ไบต์ จึงไม่ได้เพิ่มการเปลี่ยนรูปแบบ metadata
ส่วนค่าระดับ 6 ในผลทดลองด้านบนเป็นประวัติก่อนคำขอนี้
ยังไม่ได้ deploy หรือบีบอัดทับภาพเดิม และยังไม่ push การเปลี่ยนแปลงนี้เข้า main


## อัปเดต: WebP lossless

เกียรติบัตรใหม่ใช้ WebP lossless เป็นค่าเริ่มต้น แทนการเก็บ PNG ที่กล่าวไว้ในประวัติด้านบน
PNG เดิมยังรองรับครบ และ PNG_COMPRESS_LEVEL ยังคุมไฟล์ PNG ที่ดาวน์โหลดที่แปลงชั่วคราว (รุ่นปัจจุบันไม่ใช้ PNG fallback สำหรับภาพ WebP ที่ใหญ่เกิน)
รายละเอียดล่าสุดอยู่ใน [webp-storage.md](webp-storage.md)
