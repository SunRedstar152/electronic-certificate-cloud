# การเก็บเกียรติบัตรด้วย WebP lossless

## พฤติกรรม

ระบบเก็บภาพที่ออกใหม่เป็น WebP lossless method=4, quality=100, exact=True
พิกเซลของภาพ RGB เท่ากับภาพก่อนบีบอัด ความกว้างและความสูงไม่เปลี่ยน
ยังอ่าน PNG เดิม และดาวน์โหลด PNG/JPG/PDF รวมถึง ZIP ที่บรรจุ PNG ได้
PNG ที่ดาวน์โหลดจะเก็บ metadata QR เหมือนเดิม แต่อาจมีไบต์ของการบีบอัดต่างกัน
JPEG/PDF ใช้พฤติกรรมแปลงเดิม จึงไม่อ้างว่ารูปแบบเหล่านี้เป็น lossless

## Metadata และ QR

PNG ใช้ text chunk เดิม ส่วน WebP ใช้ XMP namespace urn:pkru:certificate:metadata:1
เก็บชื่อ text chunk และค่าเดิม รวมทั้ง DPI เมื่อมี และส่งต่อ ICC/EXIF
ตัวอัปเดต QR อ่านรูปแบบจริงจากข้อมูลไฟล์ ไม่อาศัยนามสกุล
เขียนไฟล์ชั่วคราว ตรวจพิกเซลนอก QR, metadata และสแกน QR ก่อน atomic replace
ถ้า URL ไม่เปลี่ยนจะไม่เขียนไฟล์ใหม่ และถ้าอัปเดตล้มเหลวจะคงไฟล์เดิมไว้
การเรียกสคริปต์ตรวจ QR ยังคงเป็นงานของผู้ดูแลเซิร์ฟเวอร์ ไม่มี endpoint สาธารณะเพิ่ม

## ผลทดลองครั้งแรก

ภาพต้นฉบับ 2000×1414 ใช้ข้อมูลและลายเซ็นสมมุติ ทดสอบแต่ละค่า 3 ครั้ง
ทุกค่าผ่านการเปรียบเทียบพิกเซล metadata และ QR

| ค่า | ขนาดรวม metadata | เวลา encode มัธยฐาน |
|---|---:|---:|
| PNG ระดับ 9 | 43,576 ไบต์ | ประมาณ 59 ms จากรอบ PNG |
| WebP method 0 / effort 75 | 35,420 ไบต์ | 28.33 ms |
| WebP method 1 / effort 75 | 12,748 ไบต์ | 55.44 ms |
| WebP method 3 / effort 75 | 12,686 ไบต์ | 59.18 ms |

| WebP method 4 / effort 100 | 12,510 ไบต์ | 71.97 ms |

จึงเลือก method 4 / effort 100: ตัวอย่างนี้เล็กลง 71.3% จาก PNG ระดับ 9
ถ้า 2 ล้านใบมีขนาดเท่าตัวอย่าง จะใช้ 25.02 GB เฉพาะไฟล์ภาพ
ผลจริงขึ้นกับแม่แบบ ข้อความ URL ใน QR และเครื่องที่ใช้ ไม่รับประกันทุกใบเท่ากัน
สคริปต์ benchmark_webp.py ใช้ URL สมมุติที่ตายตัวสำหรับทดลองซ้ำ
ขนาดอาจต่างจากตารางครั้งแรกเพราะ URL ของ QR ต่างกัน

## ข้อจำกัดและการติดตั้ง

- ไฟล์ใหม่ใช้ WebP; ไม่มีการแปลงหรือลบ PNG เดิมโดยอัตโนมัติ
- ขนาดเกิน 16,383 พิกเซลด้านใดด้านหนึ่งจะถูกปฏิเสธ ไม่ย่อภาพหรือเก็บ PNG แทน
- การดาวน์โหลด PNG ต้องใช้ CPU แปลงภาพ และ ZIP ขนาดใหญ่ต้องแปลงทีละใบ
- ผลลัพธ์ PNG ใช้ spooled temporary file; เกิน 8 MiB จะพักบนดิสก์แทนเก็บผลลัพธ์ทั้งหมดใน RAM
- ไม่เปลี่ยนสิทธิ์หน่วยงานและการบล็อกใบที่เพิกถอนใน public API
- โครงสร้างฐานข้อมูลเดิมรองรับ path ของไฟล์ทั้งสองแบบ ไม่ต้อง migration
- Dockerfile ตรวจว่า Pillow รองรับ WebP และ RAQM ระหว่าง build
- เปิดใช้ใน Docker ด้วยคำสั่งใน README; สำรองข้อมูลเดิมตามปกติ
- การตั้ง storage format กลับเป็น png มีผลต่อใบใหม่ ไม่ทำให้ WebP ที่มีอยู่เปิดไม่ได้

## การตรวจ

- Codec/QR regression 36 รายการผ่าน รวม metadata, PNG export, QR เปลี่ยน URL หลายครั้ง,
  การอัปเดตล้มเหลวไม่ทับไฟล์เดิม และการปฏิเสธภาพเกินขนาด WebP
- API/service/batch/end-to-end: 93 ผ่าน, 1 ข้ามตามเงื่อนไขสภาพแวดล้อมของชุดตรวจเดิม
- ทดสอบกับ PostgreSQL 18 ชั่วคราว ไม่ใช้ฐานข้อมูลจริง

- Docker image `pkru-certificate:webp-verified` build ผ่าน และทดสอบภาษาไทย WebP → PNG → อัปเดต QR บน Linux ผ่าน
- คอนเทนเนอร์ PostgreSQL ชั่วคราวถูกลบหลังทดสอบ ไม่ทิ้งฐานข้อมูลหรือ schema ทดสอบถาวร
- เปิดใช้เว็บจริงใน Docker แล้วเมื่อ 21 กันยายน 2026; การเปิดใช้ครั้งนี้ยังไม่ได้ push โค้ดขึ้น GitHub

## สถานะการใช้งานจริง — 21 กันยายน 2026

- `.env.docker` กำหนด `CERTIFICATE_STORAGE_FORMAT=webp` และ `WEBP_METHOD=4`
- ออกใบเดี่ยวและแบบชุดผ่านบริการสร้างเกียรติบัตรเดียวกัน จึงใช้ WebP สำหรับใบใหม่ทั้งสองทาง
- หน้าแสดงภาพส่ง MIME `image/webp`; ใบเก่า PNG ยังส่ง `image/png`
- ดาวน์โหลด PNG/JPG/PDF และ ZIP ใช้ได้ โดย ZIP บรรจุ PNG เพื่อความเข้ากันได้
- ตรวจสิทธิ์หน่วยงาน การออกซ้ำด้วย idempotency key และการเพิกถอนใช้กลไกเดิม
- ระบบสำรองข้อมูลรวมไฟล์ทุกนามสกุลใน storage จึงรวม WebP ด้วย
- ตรวจ codec/QR/ZIP 36 รายการกับ Docker image ที่ใช้งานจริงผ่านทั้งหมด โดยใช้ข้อมูลสมมุติในคอนเทนเนอร์ชั่วคราวที่ปิดเครือข่าย
- เว็บ ฐานข้อมูล PostgreSQL 18 และบริการสำรองข้อมูลผ่าน health check; ทดสอบอ่านภาพและดาวน์โหลด PNG เดิมผ่าน
- ตั้ง `QR_UPDATE_ON_STARTUP=false` เพื่อไม่เขียนทับ QR ของใบเก่าโดยอัตโนมัติ ใบใหม่ใช้ `PUBLIC_BASE_URL` ปัจจุบันตั้งแต่สร้าง
- Quick Tunnel เป็นลิงก์ชั่วคราว เมื่อเปิดใหม่ต้องตรวจลิงก์และตั้ง `PUBLIC_BASE_URL` ให้ตรงก่อนออกใบใหม่ แล้ว recreate บริการ web
- QR ที่ออกไปแล้วไม่สามารถเปลี่ยน URL บนกระดาษหรือไฟล์ที่ผู้รับดาวน์โหลดไว้ได้ การเปลี่ยนภาพบนเซิร์ฟเวอร์ไม่มีผลย้อนหลังต่อสำเนาเหล่านั้น

## อัปโหลดและล้างใบเก่า — 21 กันยายน 2026

- อัปโหลดแม่แบบเป็น PNG/JPG/JPEG เหมือนเดิม ขนาดไฟล์ไม่เกิน 10 MB และไม่เกิน 16,383 พิกเซลต่อด้าน
- ตรวจนามสกุลกับเนื้อไฟล์และ decode ก่อนแปลงเป็น WebP lossless; คงพิกเซล RGB/RGBA และความโปร่งใส ไม่ลดจำนวนสี
- แม่แบบต้นฉบับในโค้ดเก็บเป็น `background.webp`; endpoint ภาพแม่แบบส่ง MIME ตามไฟล์
- ลายเซ็น PNG รับและประมวลผลในหน่วยความจำ ก่อนรวมลงเกียรติบัตร WebP ไม่มีการเก็บลายเซ็นเป็นไฟล์ PNG แยก
- ภาพ preview และดาวน์โหลด PNG/ZIP ยังเป็นผลลัพธ์ชั่วคราวเพื่อความเข้ากันได้ ไม่เก็บสำเนา PNG ถาวรใน storage
- ผู้ใช้ยืนยันลบเฉพาะเกียรติบัตรและประวัติชุดออกใบ: ลบ 4 ใบ/4 ไฟล์; batch และ batch_rows เดิมเป็น 0
- เก็บบัญชี 2 บัญชี หน่วยงาน 1 แห่ง แม่แบบ 2 รายการ และฟอนต์เดิมไว้ครบ
- สำรองก่อนลบ `auto-20260920T172817Z-44e1a9ed` ตรวจ integrity ผ่าน; สำรองเก่าอาจยังมี PNG เพื่อกู้คืนได้
- ตรวจ API/อัปโหลด/ออกใบ/ZIP/WebP และ end-to-end ผ่าน 83 รายการกับ PostgreSQL ชั่วคราว
